## BL-1 detailed code audit and recommendation

Inspect the pinned [source tree](https://github.com/m9h/bl1/tree/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1), especially these independent source files:

- [core/izhikevich.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/core/izhikevich.py): voltage/recovery reset model; heterogeneous regular/fast-spiking populations, default E fraction .8. This is a phenomenological point-neuron model, not a reconstructed tissue preparation.
- [core/integrator.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/core/integrator.py): JAX scan, default .5 ms; external current row added to synaptic current before neuron update. Returns final neuron/synapse/STDP/excitatory weights and full boolean raster. Delay/STP carries are managed internally and are not all returned by SimulationResult; blindly re-entering simulate per control tick can reset hidden state. Surrogate and sparse modes have explicit incompatible combinations.
- [core/synapses.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/core/synapses.py): fast/slow conductance kinetics and reversal-dependent current. [network/topology.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/network/topology.py): W[post,pre], distance-dependent connectivity, separate excitatory/inhibitory weights, dense small-network builder then sparse routes. E/I fraction alone does not establish balanced dynamical activity.
- [plasticity/stdp.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/plasticity/stdp.py): trace-based LTP/LTD, default tau+20/tau−50 ms, amplitudes .005/.00525, excitatory clipping [0,.1]. STP uses release/depression/facilitation state; calibrated YAML includes E recovery 800 ms and I facilitation 1000 ms. Homeostatic rate estimator defaults 10,000 ms; structural module describes hours-scale biology but simulation calls on seconds are a modeling acceleration, not physiological evidence. Structural updates are dense-only. Inspect actual scheduling before claiming a combined four-timescale model.
- [mea/stimulation.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/mea/stimulation.py): spatial attenuation maps electrode activation into per-neuron current, so stimulation is causal. Amplitude is explicitly arbitrary model units. [mea/recording.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/mea/recording.py): many-to-many electrode mapping; count and normalized rate are different outputs. Overlapping detection footprints can count one neuron on multiple electrodes. LFP is an approximation, not a validated extracellular forward model.
- [loop/controller.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/loop/controller.py): game block scheduler retains carry, maps sensory/feedback stimulation to external current, decodes actions and steps game. Pong/Doom and fep/open_loop/silent policies are prior art, not competitive identification-control benchmarks. At the inspected game path, sensory current is tiled over steps and feedback current added at the first row; generated feedback offsets must not be assumed to be accurately delivered multiphasic waveforms.
- [compat/cl_sdk.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/compat/cl_sdk.py): redefines SDK-like classes, record() is a stub, current conversion approximates active pulses by sustained DC; this is not official SDK conformance. [tests/test_cl_sdk_compat.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/tests/test_cl_sdk_compat.py) cannot by itself establish official hardware parity.
- [validation/comparison.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/src/bl1/validation/comparison.py) and datasets.py compare simulation summary statistics to reference ranges; some power-law summaries use log-log regression. Range agreement does not establish criticality, held-out fit, mechanistic identification or evoked impulse-response fidelity.
- [configs/wagenaar_calibrated.yaml](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/configs/wagenaar_calibrated.yaml) reports 5/8 seeds meeting six broad criteria, with burst durations 95–116 ms against a 100 ms lower bound. Those are author-reported values, not our replication. [tests/test_bursting_calibration.py](https://github.com/m9h/bl1/blob/91f7c01891ebae7f17190bf81a7b7b6fe3c0cf4e/tests/test_bursting_calibration.py) uses g_exc=.50, g_inh=2, p=.02, differing from YAML .12/.36/.21. Resolve configuration drift before treating its tests and reported calibration as one model. The cited title is actually Wagenaar et al., BMC Neuroscience 7:11, DOI10.1186/1471-2202-7-11; the files' J Neurosci citation is inconsistent with the original [author publication record](https://danielwagenaar.net/pubs.html).

Benchmarks/profile_scale.py and Modal scripts exist; published A100 speed in README is **unreplicated** and cannot predict M5 performance. Full T×N inputs/history make memory and chunk state carry more important than advertised neuron count. Tests cover neurons, synapses, plasticity, delays, MEA, loops and compatibility. Inspected CI uses Python3.12 and explicitly excludes test_bursting_calibration.py and slow-marked tests, so a green standard CI cannot establish bursting calibration. None of its tests were executed here; no JAX dependency set installed to avoid a second, larger runtime qualification before the architecture choice.

Maintenance: package 0.1.0, no release returned, recent-to-audit June source and a small maintainer base. Issue index and CI workflow inspected for context; issue counts/stars are not evidence of correctness. Open issues [#4](https://github.com/m9h/bl1/issues/4), [#5](https://github.com/m9h/bl1/issues/5) and [#7](https://github.com/m9h/bl1/issues/7) concern evoked-response work, backend parity and a calibrated twin/learning comparison; their titles describe planned work, not achieved validation. No known issue is asserted resolved without a specific reproducer.

**Classification: C now (architectural prior art); potential B after qualification.** Not primary A: hidden-state continuation, physical-unit mapping, license ambiguity and calibration drift add risk without helping V0. Not categorical D: it has real stimulus-responsive dynamics and useful independent model mechanisms. Before B: obtain license clarity, pin dependency lock, reproduce short single-cell/stimulus tests, assert 2×chunk versus continuous equivalence including delays/STP/STDP, verify channel aggregation, then replicate a prespecified held-out evoked-response benchmark. No inference about living neurons follows merely from passing these.

## Cortical Labs: verified integration boundary

Official [SDK source](https://github.com/Cortical-Labs/cl-sdk/tree/a9a2f9c0cefaa032075d7cd7ccbbc4b037ba1991), [API documentation](https://docs.corticallabs.com/cl), [simulator interface](https://docs.corticallabs.com/cl/sim), [device description](https://www.corticallabs.com/cl1.html), [cloud description](https://corticallabs.com/cloud.html). Device material describes living neural cultures, silicon stimulation/recording, life support and biOS integration. Treat biOS as the device's biological/digital operating environment, not as a published neural differential equation or an API NEUROMANCER needs to reproduce. Exact device/revision channel geometry, available channels and tissue protocols must be obtained for an approved experiment; do not import BL-1's geometry or forbidden-channel constants as authoritative specifications.

CODE: src/cl/__init__.py defines StimDesign duration/current pairs, BurstDesign, Spike/Stim types. src/cl/neurons.py provides cl.open() use, stim(ChannelSet, StimDesign, optional BurstDesign, lead_time_us), loop(), read()/read_async(), record(), data streams and stim plans. Timestamp is an integer acquisition frame index. Loop analysis covers the previous half-open frame window; its right edge is decision availability. Source validators enforce ±3 µA, minimum/multiple-of-20 µs phase durations and absolute per-phase charge <=3 nC, bursts <=200 Hz; stim lead time minimum 80 µs and multiple of 40 µs. These inspected simulator constraints are not an independently verified tissue-safety envelope. Source comments about total versus per-phase charge differ; the validator loops over phases. Do not infer charge balance from validation: NEUROMANCER's eventual hardware protocol must require it explicitly.

CODE: src/cl/sim/_data_source.py exposes SimulatorDataSource, metadata, DataSourceBatch, DataSourceSpike and DataSourceStim. Pull read(from_timestamp, frame_count) returns int16 (frames,channels), plus spikes in that window; frame clock currently must be 25,000 Hz. uV_per_sample_unit scales raw samples; spike snippets are float32 µV. DataSourceStim supplies timestamp, intended_timestamp, channel, phase_durations_us and phase_currents_uA. The importable module:factory registration is reconstructed in a subprocess with JSON configuration; allocate process-local resources in open(), close idempotently. A dynamic model should declare sequential/nonseekable behavior, not promise replay-style random access. Live sources cannot assume accelerated mode support.

CODE: _sim/_data_producer.py calls on_stims before read for each block. A neural source must **queue** callbacks by event timestamp and integrate to each onset within the read; applying the current immediately on callback receipt would shift intervention earlier within the block. Buffer/read-ahead and intended-versus-delivered timestamps need dedicated conformance tests. SDK tests/cl/test_simulator_data_source.py includes read/analysis, callable/env registration, received stims and live-source latency tests; inspected, not run. A test named under_5ms is not a measured latency guarantee here.

CODE: _sim/_recording_writer.py persists samples, spike/stim tables and data streams in HDF5. Retain frame clock, uV conversion, channel map, intended/delivered stimulation and application metadata. Built-in random and replay sources have no learning/causal response; these are valid pipeline/null controls only. The new custom-source interface permits a causal simulator but does not validate one. Public developer material explicitly distinguishes simulator-only cl.sim from the device API. Hardware loop jitter behavior and simulator timing differ; no microsecond Python-controller deadline established by this audit.

**Answer: yes, an independent neural simulator can be connected to the official local SDK through a custom SimulatorDataSource.** This is an evidence-backed design path, not an implemented adapter. Keep it optional and downstream of V0; it should reuse the substrate and stimulation queue rather than replace import cl with a lookalike. At 100 µs integration and 40 µs sample periods, use a 20 µs common integer grid with event splitting, or explicitly quantify/record quantization error. Do not invent extracellular raw signals from intracellular voltage: synthetic samples must be labeled uncalibrated, or spikes-only source behavior tested.

Real CL1 use requires device access and approved living-preparation protocols; Cortical Cloud requires actual granted account/service access and provider terms. A public signup page establishes neither entitlement nor remote API endpoints, capacity, quotas or latency. No account, cloud reservation, tissue access or hardware operation attempted. Future biological execution additionally needs ethics/biosafety review, stimulation artifact characterization, tissue health controls and operator-defined limits. SDK noncommercial terms remain an integration/distribution constraint.
